JAC проверяет, есть ли в кэше ответ на запрос. Если он подходит, возвращает его. Если нет — вызывает LLM как обычно.

01 / Подключение

Как подключить JAC к агенту

При повторном запросе JAC вернёт ответ из кэша, если он ещё актуален.

  1. Установите пакет

    Клонируйте JAC и установите пакет из репозитория.

  2. Добавьте обёртку к вызову LLM

    Вызывайте функцию с теми же аргументами, что и раньше.

  3. Укажите файл кэша и срок хранения

    Ответы хранятся в SQLite. В namespace укажите модель и версию, в TTL — сколько времени ответ можно использовать.

Терминал · в каталоге репозитория
git clone https://github.com/Ishikawwwa/JAC.git

Python · ваш асинхронный вызов LLM
from jac import JAC

async with JAC(path="jac.sqlite", ttl_s=300) as cache:
    # generate — ваша существующая асинхронная функция.
    ask = cache.wrap(generate, namespace="my-llm-v1")
    first = await ask(messages=messages)
    repeat = await ask(messages=messages)

Для синхронных функций используйте with JAC(...) и обычные вызовы. Для поддерживаемых SDK доступен cache.wrap_client(client).

Для своих функций ответ должен быть совместим с JSON. Объекты поддерживаемых SDK сохраняются через кодеки. Потоковые ответы не кэшируются.

02 / Что происходит при запросе

Когда JAC возвращает ответ из кэша

Сначала JAC ищет точное совпадение. Если его нет — находит похожие запросы. Затем модель решений проверяет, подходит ли сохранённый ответ новому запросу без изменений.

04 / Свои функции вместо адаптеров

Что должны возвращать ваши функции

Если готовый адаптер не подходит, передайте свои функции. Они могут быть синхронными или асинхронными.

01 / Генерация

Генерация ответа

generate(*args, **kwargs)

Получает те же аргументы, что и исходный вызов LLM, и возвращает ответ.

ask = cache.wrap(
    generate,
    namespace="my-llm-v1",
)
  • Синхронные или асинхронные функции.
  • Ответ в формате JSON или объект SDK с поддерживаемым кодеком.
02 / Эмбеддинги

Расчёт эмбеддингов

encode(texts)

Возвращает по одному вектору на текст, в том же порядке. Массивы и тензоры должны поддерживать tolist().

CallableEmbedder(encode, identity={
    "model": "encoder", "version": "v1",
})
  • Векторы одной размерности, без NaN, бесконечностей и нулевой длины.
  • JAC может вызвать функцию одновременно из нескольких запросов. Если модель этого не поддерживает, добавьте блокировку.
03 / Решения

Проверка кэша

judge(request, candidates, kind)

Для каждого кандидата верните две оценки: эквивалентны ли запросы и отвечает ли сохранённый ответ новой просьбе.

{c.id: {"equivalent": score_a,
        "satisfies": score_b}
 for c in candidates}
  • Булевы значения или оценки от 0 до 1.
  • JAC использует ответ, только если обе оценки не ниже заданного порога.

BM25

Ищет похожие запросы по совпадению слов. Не требует модели эмбеддингов.

Эмбеддинги

Ищут похожие запросы по векторам. Можно подключить локальную модель, API или свою функцию.

Похожесть запросов ещё не означает, что ответ подходит. Это проверяет модель решений. Асинхронные функции объявляйте через async def; если результат проверки имеет неверный формат, JAC вызывает LLM.

05 / Условия использования кэша

Как не вернуть устаревший или чужой ответ

Даже при похожей формулировке ответ может отличаться. JAC также проверяет контекст, срок хранения и параметры запроса. При необходимости можно добавить свою проверку ответа.

01
Контекст

Задайте отдельный scope для каждого клиента, пользователя или контекста, который нельзя смешивать с другими.

02
Актуальность

Укажите срок хранения и версии данных, на которых основан ответ.

03
Диалог

История, системные инструкции и результаты инструментов должны совпадать.

04
Ограничения

Числа, настройки вызова и формат ответа должны совпадать.

05
Версия модели

Меняйте namespace и идентификаторы моделей при обновлении моделей, промптов или правил проверки.

06
Валидация

Передайте свой validator, если ответ должен пройти дополнительные проверки.

Python · контекст и версии зависимостей
from jac import Context, JAC

cache = JAC(
    path="jac.sqlite", ttl_s=300,
    context=Context("tenant:42", {"kb": "revision-7"}),
    validator=my_answer_validator,
)
Модель решений тоже может ошибаться. JAC не узнает сам, что данные изменились. Он также не исправит ошибку, которая уже была в сохранённом ответе LLM.

Запросы и ответы записываются в SQLite — учитывайте это при настройке доступа и хранения. Одновременные одинаковые запросы внутри одного экземпляра JAC выполняются один раз.

JAC кэширует именно вызов LLM. Если агент до этого обращается к инструментам, эти вызовы всё равно выполнятся. Потоковые ответы и неподдерживаемые форматы не кэшируются.

06 / Калибровка

Когда стоит подключать модель решений

Точный кэш работает сразу. Для похожих запросов JAC сначала нужны измерения: как часто ответ подходит и сколько времени занимает проверка.

Доля попаданий×Время генерации>Время проверки
Соберите

Возьмите запросы, для которых старый ответ подходит, и запросы, для которых нужен новый.

Проверьте

Отметьте, где ответ действительно подходит. Не используйте уверенность модели как готовую разметку.

Измерьте

Замерьте время проверки с теми моделями и настройками, которые собираетесь использовать.

По умолчанию нужно минимум 20 наблюдений. Пока нет 20 сопоставимых размеченных наблюдений, JAC не вызывает модель решений. Точный кэш и обычная генерация продолжают работать.
Python · реальные размеченные наблюдения
# Повторите для независимо проверенных тестовых данных.
ask.observe_reuse(
    request_kwargs,
    valid_hit=independently_verified_hit,
    decision_ms=measured_decision_ms,
)

В valid_hit передайте результат независимой проверки, в decision_ms — измеренное время решения.

Считайте ошибки отдельно от промахов. Если подходящий ответ отклонён, вы теряете время на генерацию. Если принят неподходящий — пользователь получает неправильный ответ.

После смены настроек повторите калибровку. Для оценки экономии нужна измеренная доля правильных попаданий, а не оценка уверенности модели.

07 / Параллельный режим

Как избежать ожидания при промахе кэша

В режиме parallel JAC запускает поиск в кэше и вызов LLM одновременно. Пользователь получает первый успешный ответ.

Поиск и проверкаГенерация, запущенная до проверки кэша

В этом примере генерация занимает 5 с, поиск — 100 мс. Небольшие расходы на запуск задач не учтены. В параллельном режиме LLM может запуститься даже при точном совпадении. Отмена не гарантирует, что провайдер не спишет оплату.

Используйте mode="parallel". При завершении приложения дождитесь фоновых задач кэша и моделей. Отмена ожидания не останавливает уже запущенную синхронную функцию или вычисление на GPU.

08 / Расчёт экономии

Сколько можно сэкономить?

Укажите время генерации, время проверки и ожидаемую долю запросов, на которые кэш сможет правильно ответить.

Пример расчёта — не результаты замеров

Среднее время = время проверки + (1 − доля попаданий) × время генерации. Здесь проверка выполняется на каждом запросе, а время генерации считается одинаковым. Вызовы инструментов до LLM не учтены.

Без кэша5,00 с
JAC · cache-first3,60 с
0 с5.10 с
28%снижение средней задержки
300вызовов LLM можно избежать на 1 000 запросов
50×во столько раз быстрее ответ при попадании в кэш
Среднее время не показывает p50 и p95. Редкие медленные запросы могут остаться такими же медленными. В режиме cache-first к ним добавится время проверки. Для оценки p50 и p95 нужны реальные замеры.

JAC пока не измеряли на H100. Значения в калькуляторе выбраны для примера и не отражают среднюю скорость API. При расчёте денег учитывайте затраты на модель решений, эмбеддинги и сервер.

09 / Тестирование

Как проверить JAC на своих задачах

Сначала можно запустить встроенные тесты без ключей API. Затем — подключить свои модели и проверить кэш на запросах вашего агента.

Поддержка / версии базы знанийСчета / схемы данныхПортфели / данные инструментовИзменённые факты / параллельные запросы
Терминал · ключи API не нужны
python -m jac evaluate-agents --offline
Терминал · ваши функции моделей
python -m jac evaluate-agents --factory my_models:build --retrieval both --mode both

Определите build() в my_models.py. Она возвращает объекты для вызова ваших моделей. Команда работает в PowerShell и Unix-оболочках.

  1. Укажите функции моделей

    Функция build() возвращает генератор, его идентификатор без ключей API, модель решений и, если нужны эмбеддинги, их модель.

  2. Сравните режимы

    Без кэша, точный кэш, BM25 и эмбеддинги — в режимах cache-first и parallel.

  3. Посмотрите время ответа и ошибки

    В отчёте есть p50/p95, число вызовов моделей, неверные ответы и случаи, когда кэш вернул неподходящий ответ.

Что именно проверяют эти тесты В офлайн-режиме ответы моделей заданы заранее — так проверяется работа самого JAC. При подключении моделей вызовы настоящие, но инструменты всё ещё заменены тестовыми данными. Вызовы API оплачиваются по тарифу провайдера.
Точный кэш можно подключить сразу.Поиск по смыслу сначала проверьте на своих данных. JAC v0.1 пока экспериментальный.
